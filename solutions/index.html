Problems where a solver has to run many times.

If a decision waits on a simulation, Evolve runs the simulations in parallel and uses each result to choose the next. These are the fields it ships with solvers for.

Aerodynamics and fluid flow

Design a nozzle, an airfoil, or a duct by running the flow solver across its parameters.

  • OpenFOAM and SU2 as ready modules, with MPI across a machine's cores
  • Optimize a geometry, or sweep conditions against test data
  • Fit a model of the whole flow field, not only the forces

Structures

Find the thickness, shape, or material that carries the load for the least weight.

  • CalculiX as a ready module
  • Sweeps and optimization over any parameter your script reads
  • Constraints on stress and displacement

Weather and atmosphere

Run forecasts and regional studies on a schedule, with each step reading the last.

  • WRF and its preprocessing as a ready module
  • Staged tasks that fetch, prepare, and run
  • Retries when a data source is late

Astrophysics

Explore a simulation's parameters and see where the physics changes.

  • Castro as a ready module
  • Python for analysis of the output
  • Many runs at once on large machines

Design databases and surrogates

Replace a slow solver with a fast model you can query in a design meeting.

  • Planned sampling of the design space
  • Surrogates fitted to your runs or to runs you already have
  • Accuracy measured before you rely on a model

Your own solver

Compile it on the toolchain, put it in your folder, and submit it like any script.

  • GCC, MPI, CMake, and the scientific libraries
  • No container to build or host
  • The same sweeps, models, and records as the built-in solvers
